No production-clean `ai_scan_attempted` or `scan_stage` rows were found in the same rolling 30-day sample. These are classified event records, not independent proof of five real customers or installed devices. Do not call them model-identification failures.

The denial screen's **Upload photo** action directly opened the browser file input, bypassing the existing iOS gallery bridge that **Pick Gallery** already used. This change routes both actions through `requestGalleryPhotoFallback`. Native selection and cancellation retain their existing handling; browser picking remains the fallback when the bridge is absent or fails. The fallback clears the `capture` attribute so it can choose an existing image after camera denial.

Two regressions failed before the change: the primary upload action never reached the native image-analysis path, and canceling the native picker contract was bypassed by opening the browser picker. Both now pass. The full suite passes **368/368**, including the installed Playwright checks, with zero failures or skips. No Swift, Android, permission, profile-verification, photo-quality threshold, purchase policy, or entitlement controls were changed.
