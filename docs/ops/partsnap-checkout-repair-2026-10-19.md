# PartSnap and checkout repair — 2026-10-19

This change fixes locally reproduced failures in evidence composition, incomplete AI responses, and the checkout experience. It does not establish the cause of the five earlier production PartSnap failures: their private records could not be refreshed because Cloudflare authentication fails.

## Resulting behavior

- The four-shot evidence sheet fits each entire photo into its cell. Portrait and wide photos retain their edge markings instead of being center-cropped. Aspect ratio is preserved; empty space is letterboxed.
- PartSnap has a 1,536-token output budget for its structured evidence response. Output stopped by `max_tokens` or `model_context_window_exceeded` is rejected, logged as `ai_response_truncated`, and passed through the existing quota-refund path. A syntactically valid but truncated response cannot become a useful result. Other scan modes retain their existing budget.
- Failed scan responses carry a bounded error code and opaque scan reference through client telemetry, allowing provider errors, malformed model JSON, and truncation to be distinguished without recording raw error messages or customer identity.
- An upgrade offer remains on its owning result surface when that surface redraws or reloads in the same session. The legacy offer event is recorded once; CTA impressions still require actual visible viewport content. Opening a manual answer again does not append duplicate cards. Other surfaces remain subject to the session offer limit, and native-store web checkout suppression remains intact.
- Upgrade handoffs use the correct catalog key for Closing Pro and Crew and show their published price. An unconfigured plan offers access requests instead of a broken Stripe continuation. A failed catalog request shows an availability message.
- A checkout failure leaves its confirmation sheet available for an intentional retry. Stripe transport failures produce the existing retryable 503/fallback path instead of escaping as a worker exception. Stripe requests share a 15-second deadline; supported browsers bound checkout requests at 35 seconds and release the pending-click lock on failure.
- The app asset query and offline cache advance together to `20261019-partsnap-checkout` and `splashlens-v53-partsnap-checkout`.
